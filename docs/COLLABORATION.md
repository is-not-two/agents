# 协作实验：C-lite（默认关闭）

## 定位与选择

现有固定 LangGraph 流程、单 Agent 和协作模式并存。比较三案：固定流程最可预测；单 Agent 灵活且调用更少；C-lite 仅用于验证分工是否带来实质收益。不引入第二套队列或图调度器，不做动态 DAG、并行扇出或递归交接。当前没有真实质量收益证据，因此保留 `config/collaboration.yaml` 的 `enabled: false`。

网页「实验协作」可以在不开模型的情况下保存白名单、创建和确认人工计划。启用真实执行需要管理员修改服务器配置、所有参与 Agent 开启生成，并由使用者明确点击可能计费的操作。配置保存不是执行授权，计划批准也不批准 Worker 写操作。

## 执行契约

1. Supervisor 复用 AgentRuntime 的模型→工具→模型循环，只能使用原有只读工具与 `propose_plan` / `call_worker` 两个协议工具。
2. `propose_plan` 返回连续编号的 `[{step, assignee, input, expected}]`。Worker 必须来自已保存的 `handoffs.allowed`。服务端冻结配置版本，模型不能指定权限、密钥、版本或其他 Worker。
3. 人工批准后顺序执行计划。Worker 是实际独立 AgentRuntime 子运行，不是把名称写进提示词。每次派发先持久化占位；结果未知时停止，不自动再派发。
4. Worker 只返回 `done`、`need_input` 或 `handoff_to` 的结构化产物。交接必须同时满足该 Worker 自己的白名单、Supervisor 白名单和已批准下一步，不创建新步骤。
5. 只读资料和真实子产物进入有大小上限的共享黑板。缺资料、非法结果、预算耗尽或未执行完整计划时只展示部分产物，不能标成成功。黑板是资料，不是权限。
6. Worker 写工具沿用原来的逐操作人工确认。父/子版本均校验；普通 Agent 接口不能确认或续接受托子运行，避免绕过共享预算。

## 预算、存储与故障

- 全链模型/工具额度取 Supervisor 上限与参与 Worker 额度之和的较小值；计划确认后只会进一步收紧。各 Worker 自身额度仍生效。协议工具、失败请求也计入共享次数，暂停后不重置。
- 额度预留先落库再外发。CAS 阻止旧版本并发推进，重复确认不重放。对于在途请求，终止不能撤回已发出的操作；需人工核对后终止，不提供盲目重试。
- 父子运行均保存在私有 `agent_session`，排除公共导出、恢复和通用历史操作。未做应用层加密；数据库备份和访问权限仍需保护。保存的审计包含输入、计划、模型/工具轨迹及真实子运行 ID。
- 不接受 API 传入脚本模型。测试用 `model_factory` 只由进程内 Python 注入；生产默认使用原有 HTTPS、禁止重定向、无自动重试的供应商边界。
- `duration_ms` 是执行段墙钟，不含人工等待；usage 与费用未知时明确 unknown，不折算为零。该实现不承诺进程崩溃后自动恢复执行。

## 可复现比较与局限

运行：`.venv/Scripts/python.exe scripts/collaboration_eval.py --report output/eval/collaboration.json`（Linux 使用虚拟环境的 `bin/python`）。quick/full 发布门禁也运行此评测。

10 条同输入任务同时经过真实固定流程、单 Agent 与协作运行时，外部模型、工具和存储使用确定性 fixture。包含原 R0 的 3 条只读检索输入，另外 27 条权限/异常任务不兼容固定只读流程，但仍完整运行原 30 条守护，报告逐条披露兼容关系，未改写原题。7 条补充任务为合成资料，不是真实使用证据。

报告记录输入 SHA、实际模型边界调用、协议工具次数、源查询、确认事件和编排耗时。自动确认不是人工试用，human_edits 为 null；未调用付费供应商，不能由此声称质量提升、真实费用或生产延迟。当前脚本产物无质量收益且协作调用更多，不能据此扩张 C-full/DAG。仍需独立授权的真实供应商对照、人工质量评分和真实业务试用，之后再作 R6 取舍。

## 验证范围

测试覆盖计划拒绝/过期版本/白名单、全链预算、逐次 Worker 写入批准、伪成功与非法交接、私有导出隔离和真实 PostgreSQL 子运行。真实浏览器覆盖默认关闭、无模型人工计划、版本冲突保留输入、刷新及 390px 布局。发布门禁未通过前不得据文档视为已验收；生产服务未因此更新。
