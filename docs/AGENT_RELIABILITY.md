# Agent 可靠性：R4a / R4b / R4c

本文按批次保留设计边界。R4a/R4b是历史范围；最新跨入口策略、工作流和长会话见R4c。真实模型质量与完整产品验收仍独立。

本批只对工具型 AgentRuntime 生效，保留固定 WorkflowService 的既有语义。
不宣称完成长期记忆、摘要质量、会话续聊或多 Agent。默认不自动记忆，不额外调用摘要模型。

## 配置（旧记录无需迁移）

通过已有 POST/PUT `/api/agents` 的 `data` 添加以下可选字段：

```json
{
  "model": {"alias": "", "temperature": null, "max_tokens": null},
  "budget": {"max_rounds": null, "max_tool_calls": null, "max_context_chars": null},
  "context": {"strategy": "window", "max_messages": 20}
}
```

- null/缺省继承管理员设置；温度缺省不向供应商传递。最大输出、轮数、工具调用、上下文预算只可收紧，不能扩大服务器上限。
- alias 只引用 `config/agent-tools.yaml` 的 `model_aliases: {fast: MODEL_NAME}`；不接收浏览器给出的模型端点或密钥，仍使用全局连接。空字符串继承全局模型。别名撤销后停止请求。
- 读取旧配置补默认值但不写库、不增加版本；旧表单更新保留未提供的新字段。嵌套字段如需更改，应发送该完整分组。
- 工具型运行的配置快照与版本继续冻结；批准写操作前再次核验配置/工具授权，预算计数跨确认暂停保留。

## 上下文边界

窗口保持系统指令和所有用户消息逐字不变，只丢弃最旧的**完整** assistant/tool 调用块。当前最新工具轮也不拆分；工具 ID、结果配对有误即拒绝，不靠删坏消息过关。

同时计算工具 Schema、模型、输出参数的请求封装字符开销。保留项仍超上限时，先报错，不发起模型请求。原始 run.messages 审计不裁剪；模型实际窗口动作记入 run.trace，可核对 dropped_messages 与前后字符数。字符数不是精确 tokenizer 数量，也不冒称 token 预算。

有损摘要暂不支持；传 summarize_window 明确报错，而不是假装已压缩。原因是当前最关键风险是丢失约束与工具协议破坏，先保留确定性窗口证据；摘要、连续会话及其真实质量反例属于 R4 后续。

## 追踪与意图

运行详情 API 的 `data.trace` 保存模型调用耗时、状态、父运行、别名及供应商响应 envelope 的 usage。未提供/无效用量为 null，费用 unknown。不会用输入字符数估算成本，也不写入 API Key。模型请求拒绝重定向，不自动重试。

`data.intent` 为零成本规则提示（search/write/smalltalk/unknown），**不构成授权，不替代确认，不宣称已完成模型兜底路由**。混合请求为 unknown。工具执行和副作用仍由现有服务权限检查与人工确认决定。

## 验证和局限

新增测试覆盖旧配置兼容、非法配置、不能提权预算、50 轮工具历史/原始审计保留、所有用户约束固定、协议损坏拒绝、跨确认轮数上限、并发配置隔离、真实回环 HTTP 参数/usage/拒绝重定向。边界替身不是模型质量证据，没有真实付费供应商调用。

后续 R4：确认式长期记忆、会话生命周期、必要的安全摘要、真实意图分支、UI 配置/追踪展示与固定流程一致性。仍须完整门禁，不能以本文件替代验收记录。

## R4b：确认式长期记忆、会话及网页工作室

Agent设置新增 `memory: {scope: none | session | persistent}`，默认none。none只保存原有运行审计，不跨运行复用；session允许同一会话ID继续提问；persistent额外投影当前已确认的本Agent长期记忆。网页「Agent工作室」可配置R4a参数、逐条提出/确认/拒绝/遗忘候选、查看会话与工具/模型追踪，旧配置表单仍兼容。

- 长期记忆为原生PostgreSQL `agent_memory`记录，有版本和决定审计。候选不能自动生效；确认需要精确确认词、记忆版本、对应Agent版本，配置变化后旧候选不可批准。所有写入在Agent行锁下，重复请求ID不重复提案，同版本不能确认两次。没有模型自动写记忆工具。
- `/api/agents/{id}/memory` GET/POST，`/{memory_id}/decide` POST；决定action为confirm/reject/forget，分别要求“确认保存长期记忆”/“拒绝记忆”/“确认遗忘”。同一用户的不同Agent不共用记忆。
- 未确认、拒绝和遗忘的内容不投影。投影为标注不可信的只读参考，不能授权工具。每次调用/批准前核对记忆指纹，记忆变化后必须新建会话，防止旧历史继续利用已撤销内容。已在途的模型请求无法撤回，遗忘不物理抹除审计正文；不要当秘密销毁功能。
- `agent_session`保存会话与完整审计，只有终态模型会话可在 `/api/agent-runs/{id}/continue` 通过版本CAS续聊。客户端只能提交新query，不能注入assistant历史。先落库running再请求模型，双标签页/旧版本不能重复调用；配置、工具权限变化、失败或待确认状态不自动续跑。所有轮次共用模型/工具预算，不因续聊或确认而清零。
- `/api/agent-runs/{id}/close` 显式结束终态会话，不撤回运行中外部操作，也不做失败重试。历史仍可审阅，关闭后不可再续聊。
- 记忆与可复用会话两种kind均不进入公共工作区JSON/Markdown导出、版本恢复或普通删除；拒绝将私密会话伪装成公共workflow_run导入执行。原因是模型回答也可能含长期记忆，不能只排除记忆表却导出回答。工作区恢复保留这些记录且拒绝ID碰撞。
- **这些新增记录未做应用层加密**，不同于wish/diary加密区；由原生数据库备份保护，不属于公共工作区备份包。不收密码、API Key或私密日记。本批未连接生产库；服务器新增kind约束需要后续已审核的管理员迁移，不宣称升级已经部署。
- 管理员可在agent-tools.yaml的limits设置max_memory_items、max_memory_chars、max_memory_context_chars、max_session_turns；缺省50/2000/12000/20。全部已确认内容装不下时请求前拒绝，不静默丢掉事实。

模型调用span通过finally落失败/耗时，异步取消或deadline到期也不丢trace，作用域参数仍重置。50轮工具历史测试现在同时要求最终assistant回答入审计，以便续聊读取完整服务器历史，而不是只存用户问题与工具结果。

本批仍未完成有损摘要质量、真实意图入口分支、固定WorkflowService的配置执行一致性、多Agent对照、真实供应商质量及生产试用；不将这些列为已完成。

## R4c：统一请求边界、固定流程策略与实际意图入口

### 请求安全与固定流程

common/provider.py集中处理模型请求：只接收HTTPS或字面回环HTTP/localhost，默认CA校验，禁止重定向、限制响应大小、不自动重试。连接保存/测试、工具型Agent与检索生成复用同一边界。旧远端明文HTTP配置不会偷偷改写；必须改为HTTPS或由管理员配置本机回环代理，才可恢复生成。未改生产配置或发送真实供应商请求。

固定answer流程现在执行所选Agent的模型别名、温度、输出上限、字符/消息预算及已确认记忆；结果冻结实际配置，记录供应商usage/耗时，缺失仍null/unknown。上限取本入口及管理员配置更严格者，不能通过Profile提权。检索范围、原始引用和生成故障回退继续保持。每次模型调用前重查Agent版本/记忆指纹，授权或事实改变即停止，不沿用旧权限。

非none记忆的固定回答存入agent_session私有kind，且其kind=answer，不伪装成可续聊工具会话。固定流程每次独立运行，session范围只存在本次流程内，不跨run复用；要多轮请用Agent工作室。相应运行列表/详情支持私有回答，公共导出/导入仍拒绝它们，避免经模型答案外泄记忆。普通none记忆的旧流程与测试替身签名保持兼容。

### 长对话：先解决已证实的消息帧上限，不发明摘要质量

context.strategy新增verbatim_window，keep_recent_users默认2、可配1–20。实测旧窗口即使字符预算足够，50个用户轮次也因所有用户消息固定而超过消息数上限。新策略先验证全部工具协议，再将较早用户原文按顺序JSON编码折叠为一个用户帧，最近若干用户消息保持原样；原始审计不修改，事件记录来源SHA、折叠数、前后字符数。

这不是LLM语义摘要：不会额外付费，不伪造遗漏的事实；旧assistant/工具结果可能移除。若最新提问明显引用旧回答（如“按上面的方案”），则提示补充依据或扩大窗口，不假装理解失去的指代。系统文本、所有用户文本和完整最新工具轮必须可保留，仍超字符预算则请求前停止。质量反例包含禁止发送/删除原文、坏工具协议不能被折叠掩盖、超预算和模糊指代；50轮实际Runtime配脚本模型只证明工程边界，不证明真实模型理解。

### 实际入口分流

普通POST /api/chat：smalltalk规则短答、写操作请求返回人工确认入口且不执行、搜索及不确定请求回只读检索；技术性“如何删除”等资料问题仍可检索。规则只决定入口，不授予权限，不把这个结果当真实模型分类准确率。问候/写入提示可在web.chat配置，不额外调用分类模型。LLM-as-classifier暂不额外收费启用：尚无实用收益证据，保留真实质量审查项。

同一接口显式提交agent_id+agent_version+generate:true可新建工具型运行；或run_id+run_version+generate:true续接服务器会话。两组互斥，只使用最后一条user问题，不采信客户端assistant历史。范围/工具以真实Agent配置为准；CAS、写操作确认、私有存储和关闭语义完全复用R4b。generate严格为布尔，字符串false不再误启用计费。

### 验收边界

使用真实回环HTTP与隔离PostgreSQL检验参数/记忆/usage/故障/重定向/明文外发禁止，浏览器验证新上下文配置持久化。旧异常响应测试只更换被替换的网络边界（urlopen→专用opener），保留所有 malformed/恢复断言。真实供应商质量、人工JD/七日试用、R5收益对照、生产授权和完整产品门禁仍未因此完成。
