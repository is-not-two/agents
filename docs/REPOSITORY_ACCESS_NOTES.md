# 仓库访问说明

记录使用 SSH 密钥访问本仓库时的通用注意事项，供维护者配置新工作环境或自动化任务时参考。

## 两种访问路径

| 路径 | 适用场景 | 凭据形态 |
|---|---|---|
| HTTPS | 交互式开发 | 账号凭据 / 个人访问令牌，由凭据管理器保存 |
| SSH | 自动化、部署 | 密钥对，公钥需登记后才能使用 |

- 账号级 SSH key 对该账号可见的所有仓库生效。
- 仓库级 Deploy key 只对该仓库生效；默认只读，需要写入时须显式开启写权限。
- 一把 deploy key 只能绑定一个仓库，多个仓库应各自使用独立密钥。

## 端口与连通性

部分网络环境会阻断 22 端口。GitHub 同时提供 443 端口的 SSH 入口，可用于连通性验证：

```text
ssh -T -p 443 -i <private_key> git@ssh.github.com
```

对应的仓库地址可写作：

```text
ssh://git@ssh.github.com:443/<owner>/<repo>.git
```

## 推送前检查

1. `git status --short --branch` 确认工作区状态。
2. `git rev-list --count origin/<branch>..HEAD` 确认确有本地提交可推。
3. `git ls-remote <remote> refs/heads/<branch>` 记录推送前的远端 SHA。
4. 推送后再次执行 `git ls-remote`，比对 SHA 是否变化 —— **命令成功不等于送达成功**。

## 安全约定

- 私钥只保存在本机，不写入仓库、不写入 CI 变量、不随文档外传。
- 不同用途（部署、审计、代码托管）使用不同密钥，避免复用同一把密钥。
- 若本机配置了 URL 重写规则，推送前应确认最终生效的远程地址，
  避免流量被改写到非预期的镜像。
