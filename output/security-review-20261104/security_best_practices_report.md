## P1-01：私密区展示的“恢复码”目前没有可用恢复链路

- **位置**：`src/rag_tech_retriever/api/routes/private.py:140-156, 162-181`；`src/rag_tech_retriever/platform/private_store.py:138-139`。
- **证据**：设置口令时生成并返回随机恢复码，但元数据的 `recovery` 使用口令而非该恢复码计算；私密路由未发现专门的恢复接口。界面和状态分别展示恢复码及 `has_recovery=true`。
- **隔离复现**：临时目录、假口令和内存替身下，设置返回 201 且返回恢复码，状态 `has_recovery=True`；用生成的恢复码换私密票据返回 401，用原假口令返回 200；恢复专用路由数量为 0。没有操作真实私密数据。
- **影响**：用户可能误以为保存恢复码后可以丢失原口令；按当前已检查的源码不能证明恢复码可以解密或找回数据，原口令遗失可能导致无法恢复。
- **建议**：立即更正文案，不要声称恢复可用；在设计安全的独立密钥包装和完整迁移策略并真实演练之前，不要擅自更改现有加密元数据或口令。提醒用户保管原口令。
- **候选缓解**：前端独立候选副本已改成提示“当前没有可用的口令找回流程，请妥善保存原口令”，本机合成浏览器测试通过；后端恢复能力未实现，原源码与线上未更改。
- **边界**：这是对本地源码及合成测试的发现，未经线上实测，不能断言特定环境当前已使用这一版本。

## P1-02：私密会话票据出现在 URL，默认访问日志会记录查询串

- **位置**：`api/routes/private.py:180-184, 221-227`，`api/static/shilie/private-view.js:91-92, 171, 221`。
- **证据**：私密读取和删除通过查询参数传递票据；路由同时接受查询参数中的口令。项目自己的 `TracerMiddleware` 仅记 path，但这不能证明 Uvicorn 或外层代理也会去除 query string。
- **隔离复现**：在临时本地回环 Uvicorn 进程发送只含假票据的 GET，默认访问日志包含该假票据。未读取服务器日志、真实票据或口令。
- **影响**：拥有访问日志、代理日志或相关监控权限的人可能获得私密解锁票据；实际利用仍受主工作台鉴权及进程会话状态影响。查询参数中直接传口令的兼容路径风险更高。
- **建议**：停止在 URL 中传递票据和口令；改为请求体或受保护的请求头，并验证反向代理、应用与错误日志均不记录敏感值。迁移时同时处理旧客户端兼容性及票据生命周期。
- **边界**：线上是否启用默认 Uvicorn 访问日志、是否存在其他日志脱敏，本轮尚未读取或验证。

## P1-03：知识表单出错时错误处理自身抛异常

- **位置**：`api/static/shilie/app.js:357-371, 447-453`；表单结构见 `api/static/shilie/views.js:60-62`。
- **证据**：`.form-actions` 位于表单内的 `.drawer-content` 中，不是 `form` 的直接子节点；原实现把它当成 `form.insertBefore` 的参照节点。
- **隔离复现**：真实 Edge 加本机合成接口返回 409；原版触发 `NotFoundError`，冲突提示未显示；候选修复后同输入可见错误与冲突弹窗、草稿保留；对独立副本回滚后相同错误复现。无真实后端写入。证据 `output/frontend-redesign-20261104/conflict-VERIFICATION.txt`。
- **影响**：用户在版本冲突或其他保存失败时可能看不到明确错误，无法正常进入设计的冲突处理流程；不代表已观察到实际数据覆盖。
- **建议**：将错误节点插入操作按钮的真实父节点，并以 409 和普通网络/服务端错误覆盖所有共用表单；候选已修改，但尚未合并到正式源码或线上。

## P2-04：私密区的“锁定”仅清除页面状态，服务端票据仍有效

- **位置**：`api/static/shilie/private-view.js:236-244, 586`；`api/routes/private.py:98-120, 162-177`。
- **证据**：前端锁定只清理当前页面变量；服务端持有全局上次口令和票据字典，没发现撤销/超时逻辑。该无口令重新换票行为在注释中被标为单用户便利设计。
- **隔离复现**：合成路由中，客户端 A 使用假口令解锁后，客户端 B 不提供私密口令换票返回 200，使用旧假票据读取也返回 200。未运行真实外层鉴权，因此这不证明未登录互联网用户能够访问。
- **影响**：在工作台主会话已被另一浏览器/设备控制、共享电脑或票据被读取的情形下，页面显示“锁定”不能保证服务端恢复二次口令边界；既有票据在进程存续期间仍有效。
- **建议**：把便捷滑块与真正锁定分开设计；锁定时服务端撤销会话并清理缓存，票据应有限期并绑定主会话。保留原有流程前应征求用户对便利性与隐私边界的选择。
- **边界**：这是在单用户假定下的授权边界和文案风险，不声称存在未鉴权远程绕过。

## P2-05：简历 DOCX 的解压规模未在解析前限制

- **位置**：`platform/resume_service.py:69-82, 112-126, 137-139`；上传请求体限制不能替代解压后大小限制。
- **证据**：DOCX 格式识别只检查 ZIP 成员名称；`python-docx` 解析之后才检查提取出的文字长度，未见 ZIP 成员解压尺寸或压缩比预检。
- **隔离复现**：本地生成的合成 DOCX 压缩包约 37,635 字节，其中 `word/document.xml` 展开约 1,001,581 字节；格式检测接受，文档解析后才因文字长度超限拒绝。没有使用真实文件或数据库，也没有进行资源耗尽测试。
- **影响**：恶意或异常高压缩比文件可能在长度限制生效前消耗大量内存；在低内存服务器上可能影响同机服务。实际最大影响取决于上传限制、库的解析约束和资源隔离。
- **建议**：解析前限制 ZIP 条目数、单成员和总解压尺寸、压缩比与重复成员；对 PDF/OCR 另设隔离的时间和资源上限，并增加小型合成压缩比反例。
- **边界**：上传接口受工作台鉴权；本次只证明检查顺序和可压缩性，不声称已造成线上拒绝服务。

## P2-06：Windows 下门禁对 UTF-8 子进程输出的解码可能丢失错误

- **位置**：`scripts/ci_gate.py:37-47`。
- **证据**：`subprocess.run(..., text=True)` 没有指定 `encoding`/`errors`；失败路径直接连接 `result.stdout + result.stderr`。
- **隔离复现**：本机默认编码 cp936，设置 `PYTHONIOENCODING=utf-8` 后，合成失败子进程输出中文“错误”；读取线程抛 `UnicodeDecodeError`，随后门禁抛 `TypeError`，未能形成正常失败摘要。未修改项目或外部环境的持久配置。
- **影响**：某些 Windows/CI 编码组合下丢失真实失败输出；失败摘要可能崩溃，成功退出的子进程输出也可能被静默丢弃。不能据此声称其他环境也受影响。
- **建议**：统一父子进程编码，或二进制采集后按明确策略解码，添加成功/失败且含中文和非法字节的回归反例。

## P2-07：静态版本门禁漏检缺少版本号的模块引用

- **位置**：`scripts/check_static_version.py:19-46`。
- **证据**：实现仅收集 `?v=数字` 并比较已找到的版本，没有检查实际 import 是否缺失版本；文件头却声称会检查缺失版本。
- **隔离复现**：仅含 `index.html` 的 `app.js?v=115` 与 `app.js` 中无版本的 `import "./feature.js"` 的临时项目，检查退出 0 并报告“全部为 v115”。
- **影响**：缓存未失效时可能混用新旧模块，造成部署后页面异常；并非已证明线上发生缓存故障。
- **建议**：解析每一个本地模块与样式/脚本引用，分别检查版本存在性和一致性，增加缺失版本、动态 import、外部 URL、注释及字符串边界反例。
- **边界**：临时合成文件复现；未对线上缓存或浏览器旧版本执行攻击或破坏性测试。
